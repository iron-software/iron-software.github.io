    SignatureDate

    The date and time of the digital signature. If left null, the signature will be timestamped at the millisecond that the PdfDocument is saved to Disk or Stream.

    The value is converted to UTC for the signature timestamp. A value whose System.DateTime.Kind is Local or Unspecified is interpreted as local time and shifted by the machine's UTC offset. Supply a Utc-kind value to record the instant unchanged.

    SignatureFieldName

    The name of an existing, unsigned signature form field to sign into. When set, signing fills that pre-existing field where the form author placed it, instead of creating a new signature field.

    Use the field names reported by PdfDocument.GetForm() (a SignatureFormField.Name). Signing throws if no unsigned field with that name exists, or if the named field is already signed.

    Leave null, empty, or whitespace to keep the default behavior of appending a new signature field.

    Cannot be combined with SignatureImage: applying a signature image rewrites the field's rectangle and page, which would move the pre-placed block. Doing so throws.

    The SignaturePermissions passed to signing are not applied on this path: filling a pre-placed field always produces an ordinary approval signature, with no DocMDP certification or document lock, even for a certification-level permission such as NoChangesAllowed. A document that ships an empty, unsigned field is not yet certified, so a fill never certifies it.

    Only one signature may be applied per open document, and this applies to plain appends too, not only the named-field path. Adding a second signature to the same open document throws NotSupportedException whether or not it was saved in between, because each signature covers the other's contents and only the last would verify. To sign several fields, sign one, save, reopen the saved bytes, then sign the next.

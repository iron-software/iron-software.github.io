    Class IronPdfConnectionConfiguration

    Configures the connection to IronPdfEngine for distributed/remote PDF processing. Use static factory methods for common configurations.

    IronPdfEngine can run locally, in Docker, or on remote servers for scalable PDF generation across distributed architectures.

    Example - Configuration scenarios:

    // Docker container (common for microservices):
IronPdf.Setting.Connection = IronPdfConnectionConfiguration.Docker;

    // Remote server with custom port:
IronPdf.Setting.Connection = IronPdfConnectionConfiguration.RemoteServer(
"https://pdf-server.mycompany.com:8080");
    

    // .NET Framework with custom channel:
IronPdf.Setting.Connection = IronPdfConnectionConfiguration.NetFrameworkChannel(
"192.168.1.100:33350");
    

    // Custom gRPC channel with metadata:
var channel = GrpcChannel.ForAddress("https://secure-server.com");
var metadata = new Metadata { { "Authorization", "Bearer token123" } };
IronPdf.Setting.Connection = IronPdfConnectionConfiguration.WithCustomChannel(
channel, metadata);

    AllowUntrustedServerCertificate

    Whether a RemoteServer connection accepts an IronPdfEngine TLS certificate that fails validation, for example a self-signed or expired certificate, or one issued for another host name.

    Example - Validate the engine's certificate now (recommended):

    var config = IronPdfConnectionConfiguration.RemoteServer("https://pdf-engine.mycompany.com");
config.AllowUntrustedServerCertificate = false;
Installation.ConnectToIronPdfHost(config);

    Declaration
    public Nullable<bool> AllowUntrustedServerCertificate { get; set; }
    Property Value
    Type Description
    System.Nullable<System.Boolean>
    Remarks
    • null (default): the certificate is accepted, as in earlier releases, and a warning is written once when it fails validation. A future release will change this default to reject such certificates.
    • false: the certificate must pass the operating system's validation, otherwise the connection fails.
    • true: any certificate is accepted, without a warning. Anyone between the application and the engine can then read or change the traffic, including documents and the license key. Prefer ServerCertificateValidationCallback to trust one specific self-signed certificate.
    Ignored when ServerCertificateValidationCallback is set, for http:// addresses and for the other connection types.

    ServerCertificateValidationCallback

    Custom validation of the IronPdfEngine TLS certificate for a RemoteServer connection. Return true to accept the certificate. When set, it takes precedence over AllowUntrustedServerCertificate.

    Example - Trust one self-signed certificate by its SHA-256 hash:

    var config = IronPdfConnectionConfiguration.RemoteServer("https://pdf-engine.internal");
config.ServerCertificateValidationCallback = (request, certificate, chain, errors) =>
{
    if (errors == SslPolicyErrors.None) return true;
    if (certificate == null) return false;
    // SHA-256 of the certificate as uppercase hex without separators (the colons that
    // openssl x509 -fingerprint -sha256 prints removed). Works on .NET Framework and .NET.
    using (var sha256 = SHA256.Create())
        return BitConverter.ToString(sha256.ComputeHash(certificate.RawData)).Replace("-", "") == "3A1F...C9";
};
Installation.ConnectToIronPdfHost(config);

    NetFrameworkChannel(String, Metadata)

    For .Net Framework project. Creates a plaintext (insecure) gRPC channel to the given address. Using this custom gRPC Channel Grpc.Core.ChannelBase for .Net Framework project.
    Since gRPC work differently in .Net Framework project. If this not working, please try remove http:// or https:// prefix in the address. Or try to create your own Grpc.Core.ChannelBase object and use WithCustomChannel(ChannelBase, Metadata)
    On .NET 6 and later the channel is created with Grpc.Net.Client, so the Grpc.Core package is not required. The address uses the Grpc.Core target forms: host:port, [ipv6]:port, dns:///host:port, ipv4:address:port or ipv6:[address]:port; the port defaults to 443 as it did in Grpc.Core. An http:// or https:// address is also accepted on .NET 6 and later.

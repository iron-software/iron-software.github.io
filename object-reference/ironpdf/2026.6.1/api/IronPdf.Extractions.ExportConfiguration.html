    Class ExportConfiguration

    Configuration for batch export operations

    Controls how tables and text are exported from a complete extraction result.

    Provides options for file organization and table option selection.

    ------------------------------------------------

    Usage: 

    var config = new ExportConfiguration
{
ExportTables = true,
ExportText = true,
TableOptions = new CsvExportOptions(),
SeparateFilePerTable = true,
FileNamePattern = "table_{page}_{index}"
};

    ExportManager.ExportResult(result, "output", config);

    ------------------------------------------------

    public class ExportConfiguration : Object

    When a completed PDF extraction needs to be written to disk and the output format, file layout, and naming have to be controlled, ExportConfiguration holds those choices in IronPDF. It is consumed exclusively by the static method ExportManager.ExportResult(PdfExtractionResult, string, ExportConfiguration). It does not perform extraction itself; extraction is the job of PdfExtractor, and the resulting PdfExtractionResult is what ExportConfiguration then governs the serialization of.

    The class fits the two-stage extract-then-export pipeline. Typical scenarios include batch invoice processing that needs every detected table written as a separate CSV file, archival workflows that export both extracted text and tables side by side into one output directory, and reporting jobs that emit one combined HTML or JSON document per source PDF. The configuration is set up once and reused across many ExportManager.ExportResult calls in a loop.

    ExportConfiguration has a single default constructor and is populated through property initializers. ExportTables and ExportText are the top-level switches that decide whether tables, text, or both are emitted (both default to true). TableOptions is typed as ExportOptionsBase and accepts any of the five format-specific subclasses: CsvExportOptions, HtmlExportOptions, JsonExportOptions, TxtExportOptions, or XmlExportOptions. The default is a bare ExportOptionsBase instance, so assigning a real format subtype is the usual first step. SeparateFilePerTable (default false) decides whether each detected table is written to its own file or batched into one. FileNamePattern (default "table_{page}_{index}") is a string template that honors the {page} and {index} placeholders; the output directory itself is the second argument to ExportManager.ExportResult.

    using IronPdf.Extractions;

PdfExtractionResult result = new PdfExtractor().Extract("invoice-batch.pdf");

// Describe what to write and how to name the files, then hand it to ExportManager.
var config = new ExportConfiguration
{
    ExportTables         = true,
    ExportText           = true,
    TableOptions         = new CsvExportOptions(),       // or Html, Json, Txt, Xml
    SeparateFilePerTable = true,
    FileNamePattern      = "invoice_{page}_table_{index}"
};

ExportManager.ExportResult(result, "output_directory", config);

    For the broader context, the parse PDFs in C# how-to covers the older single-call text extraction API that the PdfExtractor and ExportManager pipeline supersedes for table-heavy workloads. The reference for ExportOptionsBase lists the format-specific subclasses that plug into TableOptions.

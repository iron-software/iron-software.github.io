    Class ExtractionProgress

    Information about the progress of an asynchronous extraction operation.

    Used to report progress to the caller during long-running extraction operations.

    Inheritance
    System.Object
    ExtractionProgress
    Namespace: IronPdf.Extractions
    Assembly: IronPdf.dll
    Syntax
    public class ExtractionProgress : Object

    ExtractionProgress is what you receive during long-running async PDF extraction when you need to report progress to the caller. It is delivered through an IProgress<ExtractionProgress> reporter that the caller passes to the async overloads on PdfExtractor. Every property is get-only; the IronPDF runtime constructs instances and calls Report() on the supplied reporter as pages, tables, and stages complete. Application code consumes the instance, it does not populate one.

    ExtractionProgress earns its keep on any extraction job large enough to need user feedback or stage logging. Typical scenarios are document-AI pipelines extracting from hundred-page reports where a progress bar keeps users patient, server-side batch jobs that log percent-complete to a job queue, and ASP.NET Core controllers that stream live status to the browser through SignalR or server-sent events. The reporter is the lightweight, allocation-free way to feed a UI without polling.

    ExtractionProgress is wired up by passing an IProgress<ExtractionProgress> argument to PdfExtractor.ExtractAsync(pdfPath, options, progress) or PdfExtractor.ExtractPageAsync(pdfPath, pageNumber, options, progress). The five read-only properties group into three purposes. The paging trio of CurrentPage, TotalPages, and PercentComplete (computed as CurrentPage / TotalPages * 100) drives progress-bar UIs directly. The status string CurrentOperation describes the stage the extractor is in and is the field to write into a log line. The counter TablesFound tracks how many tables the table detector has surfaced so far and is useful for live metrics on table-heavy documents. The synchronous PdfExtractor.Extract and PdfExtractor.ExtractPage overloads do not accept an IProgress reporter; only the async overloads do.

    using System;
using IronPdf;
using IronPdf.Extractions;

// Pass an IProgress<ExtractionProgress> reporter to ExtractAsync.
// The runtime populates ExtractionProgress and calls Report on each update.
var progress = new Progress<ExtractionProgress>(p =>
{
    Console.WriteLine($"{p.CurrentOperation}: page {p.CurrentPage}/{p.TotalPages} " +
                      $"({p.PercentComplete:F1}%), tables found: {p.TablesFound}");
});

PdfExtractionResult result = await PdfExtractor.ExtractAsync(
    "large-report.pdf",
    options: null,
    progress: progress);
    // Single-page async with the same reporter shape.
var pageProgress = new Progress<ExtractionProgress>(p =>
{
    // Bind p.PercentComplete to a UI progress bar value (0.0 - 100.0).
});

PdfExtractionResult one = await PdfExtractor.ExtractPageAsync(
    "large-report.pdf",
    pageNumber: 12,
    options: null,
    progress: pageProgress);

    For the producer side that emits these updates, the PdfExtractor reference page covers every async overload. For the broader async pattern, the async and multithreading how-to shows the canonical IProgress plumbing, and the text and image extraction how-to covers the upstream extraction workflow that long-running jobs draw from.

    CharObjectCollection is what IronPDF returns at runtime when code reads the per-character surface of a PDF page or text run: the concrete glyph-level IList<IDocumentCharacter> implementor of IDocumentCharCollection. The element type is the interface IronSoftware.Abstractions.Pdf.IDocumentCharacter, so consuming code reads each glyph through the interface contract rather than a concrete glyph class.

    Glyph-level access matters when a higher-level text run hides what a job needs: each entry carries the positioning data and font metrics that a chunk-level TextObject reports only in aggregate. Typical scenarios include pixel-perfect drawing of overlays through the draw text and bitmap how-to, custom-font kerning analysis, and per-character bounding-box hit testing against existing page content. No public constructor is documented on the reference page.

    To obtain a CharObjectCollection, two acquisition paths are available. The page-level path reads IronPdf.Pages.PdfPage.Characters for every glyph on the page at once. The chunk-level path enumerates PdfPage.TextChunks for TextObject runs and then calls TextObject.GetGlyphInfo() on the run of interest. Both properties are statically typed as IDocumentCharCollection, so consuming code reads through the interface contract by default. The declared members on CharObjectCollection itself group into enumeration (Count, the IDocumentCharacter this[int] indexer, GetEnumerator()), random access (IndexOf(IDocumentCharacter), Contains(IDocumentCharacter)), mutation (Add(IDocumentCharacter), Insert(int, IDocumentCharacter), Remove(IDocumentCharacter), RemoveAt(int), Clear()), bulk copy (CopyTo(IDocumentCharacter[], int)), and state (IsReadOnly is read-only on this type). The access PDF DOM object how-to covers the surrounding workflow and names GetGlyphInfo directly.

    using IronPdf;
using IronPdf.Pages;
using IronSoftware;
using IronSoftware.Abstractions.Pdf;

PdfPage page = PdfDocument.FromFile("invoice.pdf").Pages[0];

// Page-level path: page.Characters returns every glyph on the page.
// Chunk-level path below scopes glyphs to one TextObject run.
foreach (TextObject run in page.TextChunks)
{
    // Both paths are statically typed as the IDocumentCharCollection contract.
    IDocumentCharCollection runChars = run.GetGlyphInfo();
    foreach (IDocumentCharacter glyph in runChars)
    {
        // Read glyph metrics through the IDocumentCharacter contract.
    }

    // Cast to the concrete type only when the indexer or IsReadOnly is required.
    if (runChars is CharObjectCollection concrete && !concrete.IsReadOnly)
    {
        IDocumentCharacter first = concrete[concrete.Count - 1];
    }
}

    For the chunk-level companion that holds the parent TextObject runs themselves, see the extract text and images how-to which covers PdfPage.TextChunks and the line-level PdfPage.Lines surface in the same DOM family.

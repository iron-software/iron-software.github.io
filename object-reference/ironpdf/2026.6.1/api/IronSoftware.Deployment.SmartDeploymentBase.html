    SmartDeploymentBase is the diagnostic handle you read to discover what IronPDF's runtime-binding layer actually resolved at startup when locating, validating, and loading the platform-specific native assemblies the rendering engine needs. Application code never instantiates this type directly. The engine selects a concrete derivative for the current operating system at startup and uses it to resolve Chromium and Pdfium binaries against the running process.

    SmartDeploymentBase matters when diagnosing runtime-binding failures: missing native assemblies, version mismatches, permission errors on the shared deployment directory, or unexpected behavior across Windows, Linux, and Docker hosts. Its properties report the binaries, paths, and versions the engine settled on, which is the difference between a configuration assertion and a runtime fact. Two abstract derivatives ship in the public API surface: PdfiumDeploymentBase for the Pdfium document layer and QPdfDeploymentBase for QPdf integration. Each branch is itself extended internally by platform-specific concrete classes that the engine constructs.

    The surface groups into four functional buckets. The deployment lifecycle is driven by Deploy() and Deploy(bool download), with Cleanup() for teardown and IsDeployed reporting state. Identity is exposed through abstract Name and AssemblyName, plus virtual OriginalAssemblyName and the Assembly reflection handle. Path resolution flows through ActualPath, Path, directory (a protected readonly string field set by the constructor), and DeploymentConfigFileName. Version resolution delegates to VersionFactory, an abstract property returning a BaseVersionFactory whose GetExpectedFileVersion, GetExpectedNuGetName, and GetExpectedNuGetVersion methods drive validation. The class also surfaces Deployments as a List<IDeployment> for composed deployments and GetPlatformSpecificErrorMessage(Exception) for translating low-level failures into messages keyed to the host platform. LoadAssemblies(string) and CheckAssemblies(string) operate on candidate paths during binding.

    using System.Reflection;
using IronPdf;
using IronSoftware.Deployment;

// Read-only diagnostic introspection of the runtime-selected deployment.
// Application code does NOT construct SmartDeploymentBase; the engine does.
void LogDeploymentState(SmartDeploymentBase d)
{
    bool deployed       = d.IsDeployed;
    string actualPath   = d.ActualPath;       // resolved native binary directory
    string configFile   = d.DeploymentConfigFileName;
    string name         = d.Name;             // implemented by the concrete derivative
    string assemblyName = d.AssemblyName;
    BaseVersionFactory vf = d.VersionFactory;

    System.Console.WriteLine($"{name} ({assemblyName}) deployed={deployed}");
    System.Console.WriteLine($"  path:     {actualPath}");
    System.Console.WriteLine($"  config:   {configFile}");
    System.Console.WriteLine($"  expected: {vf.GetExpectedNuGetName()} v{vf.GetExpectedFileVersion()}");
}

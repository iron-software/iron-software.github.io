    Interface ICidGlyphWidths

    Describes an aspect of glyph widths for a CID font

    Namespace: IronSoftware
    Assembly: IronPdf.dll
    Syntax
    public interface ICidGlyphWidths

    One slice of a PDF CID-keyed font's per-glyph width table is read through ICidGlyphWidths. It declares only two get-only members, so the contract is a read surface and nothing else. A PDF W array for a CID font is an alternating sequence of integer CID markers and width entries; each entry encodes either a single width applied to one CID or an array of widths applied to a contiguous CID run. ICidGlyphWidths represents one such entry, and the order of entries matters because each entry's meaning is anchored to the CIDs that preceded it.

    This contract matters whenever application code inspects a font that was embedded for Chinese, Japanese, Korean, or any other script that uses CID-keyed encoding. Tools that audit embedded font byte streams, validate PDF/A conformance, recompute spacing for a subset, or diagnose missing glyph metrics all read the W array through this interface. Working through the contract rather than the concrete type keeps inspection code portable and avoids binding to the slightly wider surface of the implementor.

    The two members carry the full read pattern. Check IsArray first; when it returns false, Values holds a single-element list whose one float is the shared width for the current CID, and when it returns true Values holds the array of per-CID widths for the contiguous run that the preceding CID marker opened. The Values collection comes back as an IReadOnlyList<float>, which means consumers iterate or index into it but never mutate it. Instances are obtained, not constructed: walk the GlyphWidths property on any IPdfFontObject (or on its concrete FontObject implementor), which returns an IReadOnlyList<ICidGlyphWidths> containing every slice of the source W array. The sole concrete implementor of the interface is the CidGlyphWidths class in the same IronSoftware namespace.

    using IronPdf;
using IronSoftware;
using System;

// ICidGlyphWidths is a read-only slice of a CID font's W array.
// Obtain instances from IPdfFontObject.GlyphWidths; do not new them.
void DescribeGlyphWidths(IPdfFontObject font)
{
    if (!font.IsCID) return;

    foreach (ICidGlyphWidths slice in font.GlyphWidths)
    {
        // IsArray true: Values is a run of widths. False: a single shared width.
        string shape = slice.IsArray ? "run" : "single";
        Console.WriteLine($"{shape} of {slice.Values.Count} width(s)");
    }
}

When CID glyphs render with the wrong spacing, the fonts troubleshooting guide walks the embedding-flag, subsetting, and missing-glyph-fallback cases that explain it.

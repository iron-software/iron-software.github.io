    Interface IPdfFontObjectCollection

    Collection of PDF font objects

    Namespace: IronSoftware
    Assembly: IronPdf.dll
    Syntax
    public interface IPdfFontObjectCollection : IDocumentFontObjectCollection, IList<IDocumentFontObject>, ICollection<IDocumentFontObject>, IEnumerable<IDocumentFontObject>, IEnumerable, IList<FontObject>, ICollection<FontObject>, IEnumerable<FontObject>, IJsonSerializable

    A product-neutral handle on any IronSoftware PDF font collection, with each element reachable as either a FontObject concrete or an IDocumentFontObject abstraction over the same item, is what IPdfFontObjectCollection provides. The interface declares nothing on its own: everything a caller invokes is inherited from the list and serialization contracts it composes.

    The contract belongs to the unified IronSoftware abstractions layer that several Iron Software document products share, with FontObject as the canonical concrete element. Application code can also supply its own implementor at an API boundary when stubbing a font set in unit tests, since the surface is the standard list shape plus JSON serialization. Typical scenarios include passing a font collection across a wrapper service that should accept any compatible source, JSON-serializing a font set through IJsonSerializable, and consuming a font list polymorphically without binding to one product's concrete container. Note that the IronPDF-shipped PdfDocument.Fonts property returns IronPdf.Fonts.PdfFontCollection, a separate hierarchy that traffics in IronPdf.Fonts.PdfFont, so callers working with IPdfFontObjectCollection are working with the IronSoftware shape, not with the IronPdf.Fonts container.

    The everyday surface is inherited. Each base IList<T> contributes an integer indexer (one returning IDocumentFontObject, one returning FontObject), an Add(T) overload, an Insert(int, T), a Remove(T), a Clear, a Contains(T), an IndexOf(T), and CopyTo(T[], int). The shared Count comes from ICollection<T>. The typed GetEnumerator() from IEnumerable<T> enables foreach over either element view of the same items. The font management how-to walks through the day-to-day add, embed, replace, and unembed operations on the IronPdf.Fonts side; the patterns translate when working with IPdfFontObjectCollection typed boundaries.

    using IronSoftware;
using System.Collections.Generic;

// Accept the IronSoftware font contract at the boundary - works for any
// implementor of IPdfFontObjectCollection regardless of host product.
IReadOnlyList<string> ListFontNames(IPdfFontObjectCollection fonts)
{
    List<string> names = new List<string>(fonts.Count);

    // Iterate via the FontObject element view.
    foreach (FontObject font in (IEnumerable<FontObject>)fonts)
    {
        names.Add(font.BaseFont);
    }

    return names;
}

// Add a new FontObject through the IList<FontObject> surface.
void AppendFont(IPdfFontObjectCollection fonts, FontObject incoming)
{
    fonts.Add(incoming);
}

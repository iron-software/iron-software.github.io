    Interface IPdfPathObjectCollection

    Collection of PDF path objects

    Namespace: IronSoftware
    Assembly: IronPdf.dll
    Syntax
    public interface IPdfPathObjectCollection : IDocumentPathObjectCollection<PathObject>, IEnumerable<PathObject>, IEnumerable, IList<PathObject>, ICollection<PathObject>, IJsonSerializable

    IPdfPathObjectCollection gathers the vector paths on a PDF page so code can walk them through a document's object model without binding to one concrete container, where each element is a PathObject. The contract adds nothing beyond what its base interfaces already expose, so the entire usable surface is the list shape over a single PathObject element type.

    The shipped concrete implementor is PathObjectCollection, which derives from ObservableCollection<PathObject> and is reached from pdf.Pages[i].ObjectModel.PathObjects. Application code can also supply its own implementor at API boundaries when stubbing a path set in unit tests, since the surface is the standard list shape plus JSON serialization. Typical scenarios include auditing every vector mark on a page for layout-driven redaction, removing specific strokes by index in a redaction or simplification pipeline, recoloring fills on existing diagrams in a brand-refresh job, and JSON-serializing the path set across a service boundary through IJsonSerializable. The same shape applies to the sibling IPdfImageObjectCollection and IPdfTextObjectCollection contracts reached from ObjectModel.ImageObjects and ObjectModel.TextObjects, so DOM-walking code can be parameterized over all three.

    The everyday surface is inherited. The IList<PathObject> indexer returns a single PathObject for a given integer index; Count comes from ICollection<PathObject>; Add(PathObject), Insert(int, PathObject), Remove(PathObject), RemoveAt(int), Clear, IndexOf(PathObject), Contains(PathObject), and CopyTo(PathObject[], int) come from IList<T> and ICollection<T>. The typed GetEnumerator() from IEnumerable<PathObject> enables foreach directly over the contract. The PDF DOM how-to walks through the canonical traversal pattern across TextObjects, ImageObjects, and PathObjects and demonstrates RemoveAt(i) as the documented idiom for removing a found object.

    using IronPdf;
using IronSoftware;

PdfDocument pdf = PdfDocument.FromFile("invoice.pdf");

// Accept the IronSoftware path collection contract at the boundary.
int RedactZeroLengthStrokes(IPdfPathObjectCollection paths)
{
    int removed = 0;

    // Walk back-to-front so RemoveAt indices stay valid.
    for (int i = paths.Count - 1; i >= 0; i--)
    {
        PathObject path = paths[i];
        if (path.IsStroked && path.BoundingBox.Width == 0 && path.BoundingBox.Height == 0)
        {
            paths.RemoveAt(i);
            removed++;
        }
    }

    return removed;
}

foreach (var page in pdf.Pages)
{
    RedactZeroLengthStrokes(page.ObjectModel.PathObjects);
}

pdf.SaveAs("invoice.cleaned.pdf");

    When a page's vector marks need to be read, counted, mutated, or removed as a set, PathObjectCollection is the container that holds them. There is no public constructor; the page object model owns the instance and surfaces it at PdfPage.ObjectModel.PathObjects, where ObjectModel is typed IPdfPageObjectModel and exposes the path collection alongside its sibling TextObjectCollection and ImageObjectCollection.

    Typical scenarios for the collection include auditing path geometry per page across a multi-page diagram report, redacting unwanted strokes by index through RemoveAt, inserting a PathObject returned from Clone() back into the collection, recoloring fills on existing chart shapes in a brand-refresh job, JSON-serializing the full path set on a page for downstream tooling, and reacting to in-place edits through the CollectionChanged event inherited from ObservableCollection<PathObject>. Long-lived references can subscribe to change notifications instead of polling.

    The everyday surface groups into five buckets. Mutation members are Add(PathObject), Remove(PathObject), RemoveAt(int), and Clear(). Iteration members are Count (inherited from Collection<T>), the integer indexer this[int] returning PathObject, and foreach over IEnumerable<PathObject>. State is IsReadOnly (always false in practice for the page-DOM container) and the protected Items backing list typed IList<PathObject>. Serialization is ToJson() and an overridden GetHashCode(). Observability comes from the ObservableCollection<PathObject> base, which raises CollectionChanged on add, remove, replace, move, and reset, and PropertyChanged on Count and indexer changes. One constraint that surprises in practice: when removing several paths in a single pass, iterate from Count - 1 down to 0 so the index shift after each RemoveAt does not skip entries.

    using IronPdf;
using IronPdf.Pages;
using IronSoftware;

PdfDocument pdf = PdfDocument.FromFile("diagram.pdf");

foreach (PdfPage page in pdf.Pages)
{
    PathObjectCollection paths = page.ObjectModel.PathObjects;

    // Walk in reverse so RemoveAt does not shift the next index.
    for (int i = paths.Count - 1; i >= 0; i--)
    {
        PathObject path = paths[i];

        // Drop zero-length stroked paths left over from CAD export.
        if (path.IsStroked && path.BoundingBox.Width == 0 && path.BoundingBox.Height == 0)
        {
            paths.RemoveAt(i);
        }
    }
}

pdf.SaveAs("diagram.cleaned.pdf");

    The PDF DOM object guide has a worked walk that reaches PathObjects alongside the TextObjects and ImageObjects accessors on the same page model. When the job also involves pulling text and image content out of the same documents, the extract text and images how-to documents the document-level read APIs.
